このページは、Sigma の CI についての決定事項（正）です。
CI が「自分の PC では出た」をなくす最終判定の役割を持ちます。
適用は12号からです。

## 対象

- 対象は、PR で変更された個人ファイル（`.tex`）だけです
- **全体結合（`_main`）のビルドは CI では行いません**。全体の確認は、編集担当が手元で行います

## CI が行うこと

1. **ビルド**: 変更された個人ファイルを、統一 latexmkrc（[仕様: ビルド](/spec/build/)）と TeX Live 2026 でビルドし、生成した PDF を PR の Artifacts として見られるようにします
2. **差分 PDF（latexdiff）**: PR の元になった main 版と PR の最新版を比べ、削除部分は赤の取り消し線、追加部分は青の下線で組版した PDF を作り、Artifacts に付けます。校正はソースの行差分ではなく、この PDF で行います
3. **警告 lint（chktex）**: ソースを静的検査し、組版上の問題（`$$...$$` の使用、句読点まわりのスペース、括弧の対応など）を警告として PR にコメントします。chktex で拾えない Sigma 独自のルールは、文字列検索のチェックで補います

## 運用: 最初は失敗にしない

- ビルド以外のチェック（latexdiff、chktex）は、当面は警告止まりとし、CI を失敗にはしません
- 理由は、落とすようにすると初心者が PR 自体を避けるようになるためです
- chktex には日本語文書では誤検出になる警告もあるため、うるさい警告は設定ファイル（`.chktexrc`）で番号を指定して無効化します。この調整は導入時に一度だけ行います

## latexdiff の弱点と扱い

- プリアンブルや style を変えた PR では、差分が大きく暴れることがあります。その場合は差分 PDF は参考扱いにし、通常の PDF で校正します
- 数式を大きく書き換えると、数式まるごとが削除＋追加として出ます。文章の校正用と割り切って使います
